# 项目、版本与运行记录

理解几个对象的关系后，页面上的“未保存”“第几次运行”和各种 ID 就不会混淆。

## 对象之间的关系

```text
Project 项目
  └─ Version 版本（Factor / Backtest）
       └─ Workspace 工作空间
            └─ Attempt 第 1、2、3... 次提交
                 └─ Workflow Instance 调度实例
                      └─ Task Instance 执行节点
```

Query 没有 Version：Query Project 直接关联一个 Workspace。每次重新查询都会在同一 Workspace 中创建新的 Attempt，并更新当前结果。

## 每个对象负责什么

| 对象 | 用途 | 网页中的位置 |
| --- | --- | --- |
| Project | 组织一项研究，保存名称和当前入口 | Query、Factor、Backtest 首页的项目表格 |
| Version | 固定一次成功研究的参数与结果 | 因子/回测详情页左上版本导航 |
| Workspace | 复用输出目录并归集同一研究的运行 | 工作流页的一条主记录 |
| Attempt | 保存每一次提交的输入、状态和错误 | 工作流页展开后的“运行第 N 次” |
| Workflow Instance | DolphinScheduler 中的一次实际执行 | Workflow ID 与运行详情 |
| Task Instance | 工作流内的具体节点 | Task 胶囊、日志弹窗 |

## 未保存版本

创建因子或回测项目后，页面直接显示 `v1 · 未保存`。它是一个真实、可更新的版本草稿：

- 可以重复修改参数并执行，成功结果会覆盖这个草稿当前绑定的结果；
- 可以参与页面内的结果查看；
- 点击“保存”后，当前版本固定为已保存版本，并创建下一编号的未保存草稿；
- 已保存版本的输入只读。如需继续修改，点击“基于此版本研究”或“基于此版本回测”，把参数复制到当前草稿。

版本名称/备注可以重命名，不会改变参数和结果。删除版本属于不可撤销操作，确认弹窗会明确显示影响范围。

## 为什么一次运行有多个 ID

- `workspace_id` 标识长期复用的工作空间；
- `attempt_id` 标识某次提交，排查“以前为什么能跑、现在为什么失败”时应使用它；
- `workflow_instance_id` 标识 DolphinScheduler 的实际运行，也是打开结果和日志时使用的 ID；
- `task_instance_id` 标识某个执行节点，只在读取该节点日志或执行 Task 操作时使用。

不要用项目当前参数推断历史运行。需要复现旧请求时，在工作流页打开对应 Attempt 详情，查看该次提交保存的完整请求体。
